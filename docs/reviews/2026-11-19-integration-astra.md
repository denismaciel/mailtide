# Production integration review

Reviewed main at `7c40c0e`. Three changes gate a single-mailbox shadow deployment: a hard connection cap, shared quota admission, and a durable account block. Switching the downstream pipeline also requires a replayable import feed and a per-account handover. The host can already supply delegated tokens, choose a bucket prefix, verify push independently and run migrations at deploy time.

## First deployment

**P0 · Bound the database footprint and document socket connections.** Each Python runner opens its own pool. Postgres allows eight connections, so five workers alone can occupy the entire 40-connection headroom during rollout. SQLite already pins one connection, important for in-memory databases. The URL is passed to SQLx, whose pinned Postgres parser accepts an absolute socket directory in the `host` query parameter. Document `postgresql:///app?user=worker&host=%2Fcloudsql%2Fproject%3Aregion%3Ainstance`, conventional TCP URLs and `sqlite::memory:`. Distinguish SQLx URLs from SQLAlchemy driver-qualified URLs. Add a wheel-level socket connection test and a concurrency test that observes at most two backend sessions per process. Current Postgres CI uses TCP. (`crates/mailtide-store/src/sql.rs:165–183`, `Cargo.lock:2358`, SQLx 0.9.1 `sqlx-postgres/src/options/parse.rs:69–75`, `.github/workflows/ci.yml:63`.)

**P1 · Give construction one validated contract.** Suggested immutable Python configuration and Rust equivalent, with live credentials and adapters passed separately:

```python
cfg = Config(
    database=Database(url=dsn, max_connections=2, acquire_timeout_s=5),
    blobs=Blobs(url="gs://bucket/mailtide-shadow"),
    engine=EngineSettings(), http=HttpSettings(), quota=Budget.gmail_default(),
    watch=Watch.external(), runtime=RuntimeSettings(worker_threads=2),
)
runner = Runner.open(cfg, token_source=mint_cached, quota_gate=shared_gate)
```

Use a Rust `Config { database, blobs, engine: EngineConfig, http, quota: Budget, watch: WatchMode, runtime }` and `RunnerBuilder::new(config).with_resources(...).build().await`; retain the existing generic constructor for Rust callers. Validate before opening sockets. Proposed Postgres defaults: min 0, max 2, acquire 5 s, idle 10 min, lifetime 30 min. Preserve the SQLite in-memory lifetime. Keep the existing six engine defaults in field order: active/idle polls 60/900 s, idle threshold 3600 s, watch margin 3600 s, draft settle 120 s, confirmation 60 s. Preserve the default 24-hour blob grace and job claim width four. Expose grace if the bucket has a retention requirement. Expose the six current quota limits as a unit. Check min ≤ max, positive finite timeouts, threads and budgets, poll ordering, and that configured reserves admit the largest enabled request. Allow zero draft/confirmation delay deliberately. (`crates/mailtide/src/engine.rs:38–75`, `crates/mailtide/src/quota.rs:55–92`, `crates/mailtide-py/src/lib.rs:380–414`.)

Keep Gmail’s origin and the existing 60 s request timeout. Add a bounded connect timeout (proposed 5 s), versioned user agent and optional explicit proxy. Validate the origin as an absolute HTTPS origin, allowing HTTP loopback for fakes. A proxy and an alternate origin have different credential semantics: the latter receives the bearer token. Default to polling, accept external watch ownership or a validated managed topic. The existing URL already sets the bucket prefix. Preserve the default relative key layout and its address exposure in documentation. Return the stored `blob_ref` in views and use it for reads and cleanup before supporting a different layout. Changing the bucket root needs an explicit object migration. (`crates/mailtide-io/src/transport.rs:37–71`, `crates/mailtide-io/src/blobs.rs:33–73`, `crates/mailtide-io/src/runner.rs:304–311,467–480`, `crates/mailtide-py/src/lib.rs:543–554`.)

**P0 · Share quota with every Gmail caller.** The Rust driver already accepts five resources. Python fixes four of them, including a fresh mutex-backed ledger for each runner. Workers independently spend the same project allowance, and existing send/draft calls never enter those ledgers. Expose a Python `QuotaGate` matching Rust: `admit(account, cost, priority, now_ms) -> Granted(lease) | Deferred(until_ms)`, `release(lease, bytes, now_ms)`, `cool_down(scope, until_ms)`. Bind an adapter to one project. Require atomic admission across accounts/processes, expiring leases, idempotent release and monotonic cooldown extension. Treat gate outages as infrastructure failures. Keep the local default for single-process use. Test denial, process death and a project cooldown shared by a host send and two runners. (`crates/mailtide-io/src/quota_gate.rs:15–50`, `crates/mailtide-io/src/runner.rs:126–150,277–287,352–377`, `crates/mailtide-py/src/lib.rs:344,407–413`.)

**P0 · Make a reported account block survive restart.** A revoked token sets the engine’s stop flag and queues an account-block commit. The runner returns before executing the next queued command. With the installed binding, in-memory SQLite, and a token callback raising `DelegationRevoked`, two consecutive runs both returned `blocked`, both reported zero commits, and the second called the token source again. Make the terminal transition depend on acknowledgment of its guarded commit. Propagate rejection or unknown commit outcome correctly. Expose `resume(account, expected_block_id)` to restore the saved phase after credentials are repaired. Acceptance: the next run after a committed block makes zero credential calls, including from another process. (`crates/mailtide/src/engine.rs:211–215,234–237,1147–1163`, `crates/mailtide-io/src/runner.rs:210–232`.)

## Feed and cutover

**P0 · Publish the first committed import and label removals.** Discovery, content import and relabeling all produce `Message(id)`. By the time a consumer fetches views, another change may have overwritten the relevant labels or deleted the row. The run counter increments after the blob write, before a guarded database commit. A view already includes internal date, header facts, observed/effective labels and import availability. Raw bytes are available through `read_blob`. Define versioned feed records with a stable identity `(account, seq, idx)` and kinds `discovered`, `imported`, `observed_labels_changed`, `overlay_changed`, `deleted`. Emit `imported` exactly when stored content first transitions from absent to present. Capture thread, blob reference, internal date and observed labels there so consumers can interpret SENT as of import. Include added/removed labels and, on deletion, the last known thread and labels when available. Define blob availability after deletion/grace. (`crates/mailtide/src/revision.rs:65–86`, `crates/mailtide/src/mirror.rs:1016–1033,1088–1103`, `crates/mailtide-io/src/runner.rs:467–479`, `python/mailtide/_core.pyi:40–59,123–125`.)

Append events inside the existing mirror transaction. Keep whole-commit page boundaries, including oversized pages. The host records its downstream work and page checkpoint atomically and deduplicates replay by event identity. Keep old stored ID-only entries readable as `invalidated`; their historical deltas cannot be recovered from current rows. Expose a paginated baseline snapshot with a consistent high-water token for existing databases. Bind new tokens to mailbox and feed generation to catch accidental cross-account reuse. (`crates/mailtide-store/src/sql.rs:589–600,754–805`, `crates/mailtide-store/src/conformance.rs:583–618`, `crates/mailtide/src/revision.rs:19–35`.)

**P1 · Keep a page of message views affordable.** The SQL read path loops over IDs, loading each message, tombstone, jobs, intents and seen scopes in a transaction. For 500 IDs that is roughly 2,500 reads on one of the host’s two connections. The same loader runs per eligible row during reconciliation finish while the account is locked. Implement a set-based message/intent projection for views, preserving caller order and omission of unknown IDs. Benchmark a full bootstrap and batched reads together on a two-connection pool, including finish-transaction duration. Publish typed change variants alongside the new projection. The current stub promises dictionaries, yet the unit variant `Labels` serializes to a bare string through the Python JSON conversion. (`crates/mailtide-store/src/sql.rs:403–421,428–496,1113–1125`, `crates/mailtide/src/revision.rs:65–76`, `crates/mailtide-py/src/lib.rs:526–539`, `python/mailtide/_core.pyi:34–37`.)

**P0 at handover · Fence side effects and establish a cutover watermark.** A plain `run` can claim pre-existing delivery jobs. Omitting `watch_topic` already suppresses Gmail watch calls, while the engine still schedules renewals. Offer a per-account shadow policy that rejects action admission and excludes delivery at claim time, permits mirror/blob writes in its dedicated namespace, and disables managed watch calls. Persist policy so every worker observes it. Define a transition barrier that quiesces in-flight deliveries before acknowledging a mode switch. Accept an already verified `notify(account, history_id)` that durably takes the maximum hint and lets the host coalesce work by mailbox. Startup already checks history, so today's host can schedule `run` on verified push. (`crates/mailtide/src/engine.rs:216–229,308–314,743–753`, `crates/mailtide-io/src/runner.rs:187–190,342–351`.)

During shadow, compare observed labels, message IDs, content availability and deletion at comparable revisions. Discard raced samples and report unverified rows separately. Offer `check_drift(account, sample_size, seed) -> DriftReport` through the same quota gate. Require settled backfill, fresh history and a clean comparison window. Keep verified push and watch renewal with their existing owner. Have the host persist the per-mailbox feed watermark, drain the old pipeline through the agreed boundary, then atomically select the new consumer with replay dedupe on mailbox/message identity. Retain the old checkpoint for rollback. This prevents historical imports from triggering new-mail side effects on cutover. (`SPEC.md:504–522`, `crates/mailtide/src/engine.rs:919–924`.)

## Operations and scheduling

**P1 · Read status without claiming.** Calling `run` to populate a dashboard increments the epoch and releases running jobs. Cursor timestamps and import counters initialize empty on every engine, and progress disappears in Live while imports can still be pending. Add `Store::status(&AccountId) -> Result<Option<AccountStatus>, StoreError>` and `runner.status(account)` with read-only queries, persisted last successful poll and cursor-advance times, maximum push hint, pending/blocked jobs by kind, pending imports, and classified block/cooldown scope. Unknown mailboxes return `None`. Alert on last successful poll, backlog age and sampled drift; a quiet mailbox can have an old cursor. Add `health() -> Health` checking pool acquisition and schema compatibility within a deadline. (`crates/mailtide-store/src/sql.rs:606–649`, `crates/mailtide/src/engine.rs:187–198,283–303`, `python/mailtide/_core.pyi:9–31`.)

**P1 · Bridge tracing to the host.** The driver’s blob-delete warning formats the backend error, which can contain object paths. Python block descriptions concatenate callback/provider detail. Add an opt-in runner-scoped tracing layer and bounded queue drained into Python `logging.getLogger("mailtide")` using structured `extra` fields. Attach the dispatcher to async work across thread hops. Leave handlers, JSON formatting and export with the host. Use INFO for run summaries, DEBUG for command timings, WARN for deferrals/degradation, ERROR for persistent blocks or corruption. Allowlist operation, run ID, host-supplied opaque mailbox reference, phase, stop code, duration and counts. Exclude addresses, message metadata, URL/query strings, tokens and exception text by default. Count dropped events without blocking commits. Feed a small metrics observer from the same events for run duration, confirmed imports, quota deferrals, pool waits and drift. Keep mailbox IDs out of metric labels. This works with existing logging and telemetry collectors without installing a process-global subscriber. (`crates/mailtide-io/src/runner.rs:304–311`, `crates/mailtide-py/src/lib.rs:104–113,313–339`.)

**P1 · Bound activities and propagate cancellation.** The bindings detach Python while blocking the calling thread. Each runner constructs a Tokio runtime despite the process-wide claim in the spec. Use one runner created after fork and a bounded `asyncio.to_thread` wrapper today. Budget checks occur between commands, so cancelling the awaiting coroutine or exhausting its budget can leave I/O running. Support `run(account, *, budget_s, cancel, on_progress) -> RunOutcome`. Stop starting work on cancellation, bound each dependency call, finish or resolve outstanding commits and release leases before reporting completion. Provide periodic heartbeat snapshots even during slow I/O, marshalled to the owning Python loop. Run cached synchronous token callbacks off Tokio workers; the driver requests one per Gmail command and the host owns expiry/refresh synchronization. Preserve frozen classes and stress-test callbacks and shutdown on 3.15t. Share a lazy process-local runtime and support an injected Rust runtime handle. Native awaitables via `pyo3-async-runtimes` are P2 once the cancellation contract works. (`SPEC.md:466–470`, `crates/mailtide-py/src/lib.rs:10–14,316–340,380–386,424–434`, `crates/mailtide-io/src/runner.rs:189–190,215–229,388–398`, `tests/test_end_to_end.py:193–205`.)

**P1 · Make deploy-time migrations independently callable.** The constructor already leaves DDL to `migrate()`, but a deploy job must build a runner with a token callable and blob configuration. Keep one append-only versioned SQL source and the existing transaction/advisory lock. Offer `schema_version(db)`, `migration_plan(db, target=None) -> list[Migration]` and `migrate(db, target=None)`. Ship ordered dialect-specific statements and checksums for Alembic offline review. For transactional execution on the host connection, acquire the same lock and re-read versions inside the transaction before applying and recording steps. A read-only plan must work on an empty database. Reject gaps and incompatible newer schemas at startup. Keep the existing table prefix and default namespace; allow a validated dedicated Postgres schema on every pool connection, including the migrator. Use forward-compatible expansions during rolling upgrades. Document supported binary rollback windows and explicit restore procedures for destructive upgrades. (`crates/mailtide-store/src/sql.rs:44–74,186–226`, `crates/mailtide-py/src/lib.rs:418–422`.)

**P1 · Clarify admission and exceptions.** `act` admits before running. A later exception can follow a successful admission. Identical pending intents deduplicate, but a replay after confirmation can create a fresh action. Expose `admit(account, target, action, *, request_id) -> AdmissionReceipt` with transactionally deduplicated receipts, then schedule delivery. Provide typed action constructors and distinguish invalid combinations from unknown targets, drafts and duplicates. Today failed label expansion silently maps to zero intents. Keep idle, superseded and cooldown as outcomes; expose classified infrastructure exceptions including outcome-unknown and corrupt-state. (`crates/mailtide/src/mirror.rs:537–555`, `crates/mailtide-io/src/runner.rs:171–184`, `crates/mailtide-store/src/lib.rs:28–40`, `crates/mailtide-py/src/lib.rs:71–73,225–258`.)

**P1 · Make the offline integration fixture reusable.** Ship a small `mailtide.testing` fixture using the existing fake Gmail, SQLite memory and memory blobs. Inject wall and monotonic clocks so tests can advance retry, cleanup and confirmation without sleeping. Test replay, revocation, label removal and a mailbox switching modes. Rust already has a conformant memory store. **P2**: expose it to Python when tests need direct state inspection. Python blob/HTTP adapters can likewise wait until a host needs a custom backend; current Rust traits already cover both. Skip a workflow engine, Gmail credential issuer, push service, SQLAlchemy pool adapter, arbitrary blob-key templates and bundled OpenTelemetry exporter. They add ownership and lifecycle contracts without addressing the rollout gates. (`tests/test_end_to_end.py:121–149`, `crates/mailtide-store/src/memory.rs:17–36,120–125`, `crates/mailtide-io/src/runner.rs:126–150,187–190`.)
